## How each stage went
- **Stage 1.** Environment description and shot descriptions written by me from 63/64 sampled frames (code's prompts). Seed retrieval: SigLIP2 text embeddings + saved image embeddings, top-8 per shot over every 5th frame. I then picked one frame per shot from contact sheets. 12/12 shots kept.
- **Stage 2.** ACDC's GP preference optimizer (imported unchanged), M=64 candidates, ρ_trans=1 m, ρ_rot=30°, one comparison per shot per round, judged by me from side-by-side renders. **240 comparisons in total, 50 challengers accepted, 90 ties** (20 per shot, not B=100). Every comparison, its decision and reason: `refine/state.json` (history), `refine/decisions/rNNN.txt`, sheets `refine/sheets/`. Refined poses: `refine/all_best_results.json`.
- **Stage 3.** ACDC code unchanged: A* + safe-corridor gates (`run_trajectory_generation.py`), TOGT (`run_togt_scenes.py`, including its own clearance re-optimization retries), RotationSpline camera orientation. Outputs in `stage3/`.

## Deviations from the design (and why)
1. **Refinement budget ~20 comparisons/shot instead of B=100.** I judge each pair by eye; 100 × ~12 shots × 6 runs was not possible. Refinement was also stopped when I ran out of time (a partly judged round was discarded).
2. **Optimizer perturbs the full 3-D rotation (code behaviour)**, whereas the paper says position+yaw with roll/pitch fixed to 0. I kept the code. Consequently roll/pitch in the final are not 0 (see checks); the saved ACDC output has the same property.
3. Pair judgments were made on a sheet showing incumbent (image 1) and challenger (image 2) side by side at 480×270 each, several shots per sheet; ties ("3") were allowed as in the code. Refinement renders used ACDC's own Blender script (8 spp CPU) on the patched mesh.
4. Environment description / shots were written once per scene and shared by the scene's two prompts. The last exploration frame was not viewed.
5. Text embedding: only the SigLIP2 text tower of the RADIO adaptor was run (fp16 weights, fp32 compute) to fit the memory cap; image embeddings and occupancy grids were the saved precomputed ones (grids built from the original meshes).
6. Final video: patched mesh + patched renderer (as instructed), via `tools/make_video_mine.py` (frames piped to ffmpeg in chunks to save disk); same resolution/fps/FOV as saved video.
7. A first retrieval attempt had a bug in my text-embedding wrapper (garbage embeddings); discarded and redone (`stage1/invalid_attempt1_meta_bug/`).

## Checks
| check | result |
|---|---|
| bundle `validate_trajectory` | PASS (occupied samples 0, max gate error 0.0072 m) |
| speed ≤ 1.0 m/s | FAIL (max 1.084) |
| tilt ≤ 30°, body rate ≤ 10.2 rad/s, thrust within [0.1,7.2] N/motor | PASS (tilt 4.1°, rate 0.05, thrust 2.04–2.16) |
| clearance ≥ 0.3 m from occupied voxels | FAIL (min 0.023 m; 45% of samples below 0.3 m) |
| roll = 0 | FAIL (max |roll| 42.3°) |
| pitch within ±25° | FAIL (max |pitch| 50.3°) |

Note: the clearance and roll/pitch figures are measured on the delivered centerline/CSV; the saved ACDC output measured the same way: min clearance 0.091 m, max |roll| 6.9°, max |pitch| 19.3°, max speed 1.057 m/s.
